## Blocking standards findings

### P1 — performer-name lookup is not tenant-scoped

**Evidence**

- `src/backend/models/hospitalization.repository.ts:32` loads `performedByUser` as a Prisma relation with only `{ id, name }`.
- Prisma query logging shows the nested user lookup filters only by `users.id`, not `users.tenantId`.

**Why this blocks sign-off**

Project DB rules require every query on a tenant-scoped table to include `tenantId`. Today the authenticated write path normally prevents a cross-tenant performer id, but malformed/imported legacy data could resolve a different tenant's staff name. Existing tests prove outer hospitalization isolation, not this malformed-relation case.

**Required fix**

Resolve performer names using a tenant-scoped user query (batch IDs and map back to care logs), or redesign the FK as a tenant-aware composite relation after DB review. Add a regression fixture with a care row whose performer points at a different tenant and assert the response never returns that name.

### P1 — new `performedBy` foreign key has no supporting index

**Evidence**

- `src/backend/prisma/migrations/20260711140000_add_care_performed_by_fk/migration.sql:14-15` adds the FK.
- `src/backend/prisma/schema.prisma:653` has `(tenantId, hospitalizationId, recordedAt)` only; no index begins with `performedBy`.

**Required fix**

Add an indexed access path for `performedBy` using the project's live-table migration rules, update Prisma schema, and add migration verification. This is required by the repository DB-agent rule for every new FK.

### P1 — undefined typography token in the new modal

**Evidence**

- `src/frontend/src/views/clinic/ClinicInpatient.tsx:226,261,274` uses `text-label-lg`.
- The approved design token references and `tailwind.config.js` do not define `text-label-lg`.

**Required fix**

Use an existing documented token (normally `text-label-md`) or add a deliberately specified token through the design-system process. Do not leave an unknown Tailwind utility that silently has no CSS effect.
