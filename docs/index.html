📝 Functional Requirements

Multi-Tenancy & Auth

  • Each clinic is an isolated Tenant with its own subdomain
  • Users belong to one Tenant; roles: admin, doctor, staff
  • JWT tokens embed tenant_id and role; middleware enforces both
  • Admin can manage clinic users, settings, and subscription

Module 1 — Pet & Owner Management

  • Create/edit Owner profiles (name, phone, email)
  • Create/edit Pet profiles linked to Owner (species, breed, birth date, gender, weight, microchip ID, photo)
  • Quick Search: find by pet name, owner phone number, or microchip ID
  • 🖥️ Tablet: capture pet photo directly from device camera
  • Flag pets for disease surveillance / isolation alerts

Module 2 — Appointment Scheduling

  • Calendar views: per doctor, per exam room; day and week views
  • Create/reschedule/cancel appointments with reason notes
  • Auto-send SMS/LINE reminder to owner 24h and 1h before appointment
  • 🖥️ Tablet: doctor can view daily schedule in a compact card layout

Module 3 — EMR

  • SOAP-format entry: Subjective, Objective, Assessment, Plan
  • Treatment timeline showing all past visits in chronological order
  • Prescription issuance linked to Inventory (auto-deducts stock)
  • Lab order and result upload (PDF, image)
  • 🖥️ Tablet: stylus/finger drawing on animal anatomy diagrams

Module 4 — Inventory Management

  • Drug and supply catalog with unit, minimum stock level, expiry date
  • Auto-deduct stock quantity when prescription is issued via EMR
  • Alerts: stock below minimum threshold; items expiring within 30 days
  • 🖥️ Tablet: scan drug barcode/QR code via camera

Module 5 — Billing & POS

  • Generate invoice from EMR visit (services + drugs)
  • Issue tax receipt and prescription printout (PDF)
  • Payment methods: cash, QR code (PromptPay), credit/debit card
  • 🖥️ Tablet: display QR code full-screen for owner to scan and pay

Module 6 — Inventory & Multi-Branch Transfers

  • Smart inventory management system with stock catalog (medicines, vaccines, general products)
  • Physical inventory levels, lot numbers, and expiration dates isolated per branch in branch_inventory
  • Automatic stock deduction on EMR prescription dispensing or retail POS checkout
  • Inter-branch inventory transfer system with request, dispatch, and receipt confirmation workflows
  • Lot/expiry tracking, low-stock threshold triggers, and real-time alerts
  • 🖥️ Tablet: barcode/QR scanning via camera for swift catalog registration and search

Module 7 — Billing, POS & Discount Engine

  • Automatic invoice generation pulling clinical items directly from EMR visits
  • Retail POS checkout screen for over-the-counter pet shop sales
  • Flexible discount engine supporting tiered membership cuts, flat rates, and product-specific promotions
  • Multiple payment schemes: Cash with change calculations, credit cards, bank transfers, and PromptPay
  • Generation and printing of detailed receipts, invoices, and VAT (7%) tax documents
  • 🖥️ Tablet: full-screen PromptPay dynamic QR code rendering for scans

Module 8 — Inpatient (Hospitalization) Management

  • Admission tracking including cage assignment, admission reasons, and responsible veterinarian
  • Daily nursing plans structured into hourly time-slots (e.g. 08:00, 12:00, 16:00, 20:00)
  • Tracking of vital signs (temp, pulse, resp), feeding schedules, and administered medications
  • Discharge automation compiling hospitalization logs and cage room charges directly into billing invoices

Module 9 — Grooming Management

  • Grooming appointments scheduling including service selection, specific request notes, and groomer assignment
  • Daily service capacity tracking to prevent groomer overbooking based on slot time limits
  • Real-time status tracking queue (scheduled, in_progress, completed, cancelled) segregated from clinical queues

Module 10 — Blood Bank Management

  • Blood donor registry logging pet details, eligibility status, blood type, and physical health records
  • Donation logs tracking volume, collection date, expiry, and storage status (available, used, expired)
  • Transfusion logs tracking recipient compatibility, cross-matching results, and post-transfusion reactions

Module 11 — Loyalty & Membership System

  • Tiered membership programs (Gold, Platinum, etc.) with custom checkout discount engines
  • Automatic loyalty point accumulation based on invoice amounts (e.g. ฿100 spent = 1 point)
  • Cash redemption or reward exchange flows integrated directly into the POS/Billing screens

Module 12 — Security & Activity Monitoring

  • User activity audit trail logging every modification/deletion of billing, medical records, or stock adjustments
  • Secure, immutable audit records storing user ID, action description, modified tables, changes diff, IP address, and timestamp
  • Work-hour restrictions preventing specific staff logins outside designated time windows

Module 13 — Reports & Analytics Dashboard

  • Dynamic revenue analysis reporting daily, monthly, and yearly branch performance
  • Popularity metrics showcasing top-performing clinical services and best-selling retail products
  • Real-time operational snapshot showing inpatient occupancy rates, pending grooming counts, and appointment loads

Code Style

  • Explicit return types on all exported functions
  • No any types — define interfaces for all API shapes

🧪 QA Agent — Quality Assurance & Validator

📁File: .claude/agents/qa-agent.md · Invoke: @qa-agent

Test Categories

1. Data Isolation

  • Tenant A cannot read, update, or delete Tenant B's records
  • JWT with expired/missing tenant_id rejected at middleware
  • Direct DB ID guessing across tenants returns 403/404

2. Input Validation

  • Negative or zero values for numeric fields
  • Empty required fields → 400 with field name
  • Strings exceeding column varchar limit → 400 (not 500)

3. Concurrent / Network Edge Cases

  • Double-submit (rapid tap of Save) → idempotent or 409
  • Network drop mid-save → DB not in partial state
  • Stale cache after concurrent update

4. RBAC

  • Staff cannot access doctor-only routes → 403
  • Doctor cannot access admin-only routes → 403
  • No token → 401

Test Output Format

Test Suite: <module>-<task-id>
Test: <test name>
Given: <precondition>
When: <action>
Then: <expected result>
Type: happy_path | edge_case | security | ui
