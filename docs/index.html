Module Detail

M1 — Pet & Owner

  • Owner: name, phone (unique per tenant), email, LINE user ID, membership tier, loyalty points
  • Pet: linked to owner; species, breed, DOB, weight, microchip (unique per tenant), allergies, underlying conditions, photo URL, isolation flag
  • Quick search returns top 10 results by name / phone / microchip in <300ms
  • 🖥️ Tablet: camera capture for pet photo; barcode scan for microchip lookup

M2 — Appointments

  • Calendar per doctor and per room; day and week views
  • Double-booking (same doctor + time) → 409 Conflict
  • Status: scheduled → confirmed → in_progress → completed / cancelled / no_show
  • Walk-in appointments bypass slot conflict check
  • Reminder cron fires daily at 08:00; marks pet_reminders rows as sent (LINE/SMS dispatch deferred)
  • 🖥️ Tablet: compact daily card layout; 44px tap targets on all status buttons

M3 — EMR

  • SOAP note: Subjective, Objective (vitals), Assessment, Plan
  • Anatomy canvas: stylus/finger annotation on dog/cat body diagram (Konva.js)
  • Prescriptions auto-deduct branch_inventory atomically on creation; restore on cancellation
  • Attachments: lab results, X-rays (PDF/image) stored via S3 signed URL (deferred)
  • Record locks to billed on invoice creation — no further edits allowed
  • Vaccination timeline linked to medical record; due-date query for reminder cron

M4 — Inventory

  • Product catalog: name, SKU, barcode, unit, unit price, category, min_stock_qty
  • Per-branch stock in branch_inventory: lot number, expiry date, current qty
  • Alerts: red (stock = 0), amber (stock < min or expiry < 30 days)
  • All movements logged in stock_movements (prescription_dispense, stock_in, adjustment, transfer_out, transfer_in)
  • 🖥️ Tablet: ZXing.js camera scan → auto-fills product search

M5 — Billing / POS

  • Invoice auto-generated from EMR on lock; manual retail POS also supported
  • Line items: service fees + prescribed drugs pulled automatically
  • Discount engine: membership tier flat-rate, per-product promotions
  • VAT 7% applied on subtotal after discounts
  • Payment: Cash (change calc), PromptPay QR (EMVCo, UI only — gateway deferred), Credit card (deferred)
  • Void creates reversal audit record; original invoice immutable
  • 🖥️ Tablet: full-screen QR for owner to scan; large payment method tiles (80px)

M6 — Reports

  • GET /api/reports/revenue?period=daily|monthly
  • GET /api/reports/top-services — top-earning service types
  • GET /api/reports/branch-revenue — bar chart data per branch
  • All queries strictly tenant-scoped; <1s using pre-aggregated COUNT + SUM

M7 — Multi-Branch & Transfers

  • Branch CRUD with operating hours; doctor shifts (doctor_shifts) prevent booking outside shift
  • Transfer request → dispatch → receive; dual stock_movements rows in a single DB transaction
  • Source branch stock deducted only on receive confirmation

M8 — Inpatient

  • Admit: cage number, responsible doctor, reason; status: admitted / discharged
  • Daily care log at defined time slots (08:00, 12:00, 16:00, 20:00): temp, pulse, resp, feeding, meds
  • Discharge auto-creates billing invoice including cage/day charges

M9 — Grooming

  • Grooming booking with service type, groomer assignment, special notes
  • Daily capacity quota per groomer — overbooking → 409
  • Queue board: scheduled → in_progress → completed / cancelled

M10 — Blood Bank

  • Donor registry: pet, blood type, eligibility, last donation date (56-day minimum interval)
  • Donation: volume, collection date, expiry date (30 days), status: available / used / expired
  • Transfusion: compatibility guard (blood type match required at API level), reaction log

M11 — Loyalty

  • Membership tiers on owner: Standard / Gold / Platinum — each tier has configurable discount %
  • Points: ฿100 spent = 1 point (earn on invoice payment)
  • Redemption at POS; loyalty_transactions records every earn/redeem event

M12 — Audit & Work Hours

  • auditMiddleware wired on billing, medical records, and stock adjustment routes
  • Audit log fields: user, action (INSERT/UPDATE/DELETE), table, record ID, diff JSON, IP, timestamp
  • Records are immutable — no UPDATE/DELETE permitted on audit_logs
  • Login blocked outside allowed_start_time–allowed_end_time window if set on user

M13 — Reminders

  • Background cron (configurable schedule, default 08:00 daily) queries appointments due tomorrow
  • Creates pet_reminders rows; currently marks sent without actual dispatch
  • LINE dispatch deferred (requires LINE_CHANNEL_ACCESS_TOKEN); SMS fallback via Twilio also deferred
  • Manual trigger: POST /api/reminders/trigger (admin token)

Database Security Checklist

  • ทุก Query มี WHERE tenant_id = :tenantId (หรือ Prisma where clause)

API Security Checklist

  • RBAC ตรวจสอบ role ก่อน action (ไม่ใช้ client-provided role)
  • Response ไม่ include password_hash หรือ field ที่ sensitive
  • File upload: ตรวจสอบ MIME type จาก magic bytes (ไม่ใช่ extension)
  • Input validation ด้วย Zod ทุก endpoint
