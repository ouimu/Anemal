# Appointment Doctor-List Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the appointment-booking doctor dropdown, which is currently empty for `clinic_staff` and `doctor` role users (only `clinic_admin` can populate it today), blocking appointment creation.

**Architecture:** Replace the frontend's use of the admin-only `GET /users` endpoint with a new, narrowly-scoped `GET /api/appointments/doctors` endpoint gated by `appointments.view` (a permission all three clinic roles hold). Branch scope comes exclusively from the authenticated session (`req.context.branchId`), never a client param. Doctor membership is resolved via `UserRole → ClinicRole`, matching either the system `doctor` role directly or a tenant custom role whose new `sourceRoleId` column traces back to it.

**Tech Stack:** Node.js/Express/Prisma/PostgreSQL backend, React/TanStack-Query/Tailwind frontend, Jest/Supertest for backend tests.

## Global Constraints

- Every DB query touching `User`, `UserRole`, or `UserBranch` MUST filter `tenantId` — multi-tenancy is non-negotiable (CLAUDE.md).
- Branch scope MUST come only from `req.context.branchId` — never a client-supplied query param or body field (grill Q1, ADR-0002).
- Response from the new endpoint MUST be `{ id, name }` only — no email/phone/username (BA-5).
- Exclude `User.isActive = false` always (BA-4).
- No backfill migration for pre-existing Doctor-clone roles in this plan — DB-2 is a read-only check; a data-fix task is added to this plan's scope ONLY if DB-2 finds affected rows, per BA's conditional-trigger ruling.

```typescript
/**
 * Users bookable as a doctor for the given branch scope.
 * branchId === null means "no branch filter" (all-branches session), matching
 * the same convention findInRange already uses.
 * Doctor membership: any assigned role is either the system 'doctor' role
 * directly, or a custom role whose sourceRoleId traces back to it.
 */
export async function findDoctorsForBranch(tenantId: number, branchId: number | null) {
  const doctorSystemRole = await prisma.clinicRole.findFirst({
    where:  { key: 'doctor', tenantId: null, isSystem: true },
    select: { id: true },
  })
  const doctorRoleMatch = doctorSystemRole
    ? [{ key: 'doctor' }, { sourceRoleId: doctorSystemRole.id }]
    : [{ key: 'doctor' }]

  return prisma.user.findMany({
    where: {
      tenantId,
      isActive: true,
      ...(branchId != null ? { userBranches: { some: { tenantId, branchId } } } : {}),
      userRoles: {
        some: {
          tenantId,
          role: { OR: doctorRoleMatch },
        },
      },
    },
    select:  { id: true, name: true },
    orderBy: { name: 'asc' },
  })
}
```
