# รอการตัดสินใจ — ตัวเชื่อมต่อ OneDrive สำหรับเก็บไฟล์คลินิก (โครงการย่อยที่ 3 จาก 3)

**สถานะ:** รอคำตอบจากเจ้าของผลิตภัณฑ์ (ผู้ใช้) — ยังไม่เริ่มขั้นตอน BA sign-off / grill / write-plan
**เอกสารฉบับเต็ม (ภาษาอังกฤษ, รายละเอียดทางเทคนิค):** `docs/superpowers/specs/2026-07-23-storage-onedrive-driver-design.md`

---

## สรุปสถานะโครงการ

ระบบให้แต่ละคลินิกเลือกที่เก็บไฟล์ (รูปสัตว์เลี้ยง + เอกสารแนบประวัติการรักษา) ของตัวเอง มี 3 ทางเลือกตามแผน:

1. **เครือข่ายแชร์ไฟล์ของคลินิกเอง (SMB)** — เสร็จแล้ว ใช้งานได้จริง
2. **Google Drive** — เสร็จแล้ว ใช้งานได้จริง
3. **Microsoft OneDrive** — ยังไม่เริ่มทำ ติดคำถาม 4 ข้อด้านล่าง ต้องตอบก่อนถึงจะออกแบบต่อและเริ่มเขียนโค้ดได้

ไม่มีการเดาคำตอบเอง เพราะเป็นการตัดสินใจเชิงธุรกิจที่ต้องให้คนตัดสินใจ

---

## คำถามที่ 1 — คลินิกควรเชื่อมต่อบัญชี Microsoft แบบไหนได้บ้าง?

Microsoft มีบัญชี 2 แบบ:
- **บัญชีส่วนตัว** (OneDrive ฟรีทั่วไป เหมือนบัญชี Gmail ส่วนตัว)
- **บัญชีองค์กร/โรงเรียน** (Microsoft 365 ที่บริษัทจ่ายเงินซื้อ)

Anemal ขายให้ธุรกิจ คลินิกส่วนใหญ่ที่ใช้ Microsoft มักมี Microsoft 365 แบบจ่ายเงิน แต่คลินิกเล็กบางแห่งอาจมีแค่บัญชีส่วนตัวของเจ้าของ

**ทางเลือก:**
- (ก) รับเฉพาะบัญชีองค์กร/โรงเรียน
- (ข) รับเฉพาะบัญชีส่วนตัว
- (ค) รับทั้งสองแบบ

**ข้อเสนอแนะจากทีม BA: (ค) รับทั้งสองแบบ** — ตั้งค่าฝั่ง Microsoft แค่จุดเดียว โค้ดเหมือนกันหมด ไม่ปิดกั้นคลินิกเล็ก (Google Drive ที่ทำไปแล้วก็รองรับทั้งสองแบบในทางปฏิบัติเช่นกัน)

---

## คำถามที่ 2 — ไฟล์ของคลินิกควรเก็บไว้ตรงไหนใน OneDrive ของเขา?

Microsoft ให้เลือกได้ 2 แบบ แลกกันระหว่างความเป็นส่วนตัวกับความสะดวกในการมองเห็น:

- **(ก) โฟลเดอร์แอปส่วนตัว (แนะนำ)** — Anemal เห็น**เฉพาะโฟลเดอร์ของตัวเอง**เท่านั้น ไม่เห็นไฟล์อื่นในบัญชี OneDrive ของคลินิกเลย โฟลเดอร์จะอยู่ที่ `Apps/<ชื่อแอปที่จดทะเบียน>/` เหมือนวิธีที่ทำกับ Google Drive ไปแล้ว
- **(ข) โฟลเดอร์ "Anemal" ที่มองเห็นชัดเจนอยู่หน้าแรก OneDrive** — สวยงามหาง่ายกว่า แต่ต้องขอสิทธิ์เข้าถึง**ไฟล์ทั้งหมด**ใน OneDrive ของคลินิก ซึ่งกว้างเกินความจำเป็น

**ข้อเสนอแนะจากทีม BA: (ก)** — ใช้หลักการเดียวกับที่ล็อกไว้แล้วตอนทำ Google Drive (ขอสิทธิ์เท่าที่จำเป็นเท่านั้น)

---

## คำถามที่ 3 — คุณ (ผู้ดูแลระบบ) ต้องเป็นคนสร้างการลงทะเบียนแอปกับ Microsoft — ขอยืนยันและช่วยตั้งชื่อ

เหมือนตอนที่คุณสร้างโปรเจกต์ "Anemal Access GDrive" ใน Google Cloud ต้องมีคนไปสร้าง **app registration** ฟรีใน Microsoft Entra (Azure) โดยต้องใช้ข้อมูล: ประเภทบัญชีจากคำถามที่ 1, ที่อยู่ redirect `http://localhost:4000/oauth/onedrive/callback` (จะเพิ่มที่อยู่จริงตอน deploy เหมือน Google), แล้วเอา Client ID + Client Secret ไปใส่ในไฟล์ตั้งค่า `.env` ของระบบ

มี 2 เรื่องที่ต้องตัดสินใจ/รับทราบ:

1. **ชื่อที่แสดง:** ชื่อนี้จะเป็นชื่อที่คลินิกเห็นตอนกดยินยอมเชื่อมต่อ และ (ถ้าเลือกข้อ ก ในคำถามที่ 2) จะกลายเป็นชื่อโฟลเดอร์ใน OneDrive ของคลินิกด้วย (`Apps/<ชื่อที่แสดง>/`) ทีม BA เสนอชื่อ **"Anemal"** เฉยๆ ขอยืนยันชื่อนี้ได้ไหม หรืออยากใช้ชื่ออื่น?
2. **Client Secret จะหมดอายุ** (Microsoft กำหนดสูงสุด 24 เดือน แนะนำ 6 เดือน) ต่างจาก Google ตรงที่อันนี้ต้องสร้างใหม่แล้วเอาไปใส่ `.env` ก่อนหมดอายุ ไม่งั้นการเชื่อมต่อ OneDrive ของทุกคลินิกจะหยุดทำงานพร้อมกัน **คุณรับที่จะเป็นคนคอยทำเรื่องนี้ไหม** (แค่ตั้งเตือนในปฏิทินก็พอ)?

---

## คำถามที่ 4 — บางคลินิกฝ่าย IT จะต้องอนุมัติ Anemal ก่อนใช้งานได้ — ยอมรับความยุ่งยากนี้ไหม?

สำหรับคลินิกที่ใช้บัญชี**องค์กร/โรงเรียน** ผู้ดูแลระบบ Microsoft ของคลินิกอาจเห็นหน้าจอ "ต้องขออนุมัติจากแอดมิน" แทนที่จะกดยินยอมเองได้เลย เพราะ (1) หลายบริษัทปิดการอนุมัติด้วยตัวเองของพนักงาน และ (2) Microsoft จำกัดสิทธิ์นี้กับแอปที่ยังไม่ผ่านโปรแกรม "publisher verification" (ซึ่งต้องมีบัญชี Microsoft partner — เอกสารเพิ่มเติมฝั่งเรา)

**ทางเลือก:**
- (ก) ยอมรับสำหรับเวอร์ชันแรก — คลินิกที่เจอปัญหานี้ให้ขอแอดมิน IT ของตัวเองกดอนุมัติครั้งเดียว เราจะเขียนคำอธิบายสั้นๆ ไว้ในหน้าเชื่อมต่อ
- (ข) ทำเรื่อง publisher verification กับ Microsoft ให้เสร็จก่อนเปิดใช้งาน

**ข้อเสนอแนะจากทีม BA: (ก) สำหรับเวอร์ชันแรก** — เรื่อง verification ทำทีหลังได้โดยไม่ต้องแก้โค้ด

---

## ข้อมูลเพิ่มเติม (ไม่ต้องตัดสินใจ แต่ควรรู้ไว้)

ต่างจาก Google, **Microsoft ไม่มีวิธีให้ระบบของเรายกเลิกสิทธิ์การเข้าถึงของตัวเองได้** เวลาคลินิกกด "ยกเลิกการเชื่อมต่อ" ระบบจะยังทำงานถูกต้องตามที่ออกแบบไว้ (เราลบกุญแจที่เก็บไว้ทันที ทำให้ Anemal เข้าถึงบัญชีนั้นไม่ได้จริงๆ) — แต่รายชื่อ Anemal จะยังค้างอยู่ในหน้าตั้งค่าบัญชี Microsoft ของคลินิก จนกว่าคลินิกจะไปลบเองด้วยมือ ข้อความยืนยันตอนยกเลิกการเชื่อมต่อจะบอกเรื่องนี้ตรงๆ พร้อมลิงก์ไปหน้าที่ถูกต้องของ Microsoft ไม่มีทางเลือกอื่นให้เสนอ จึงเป็นแค่ข้อมูลแจ้งให้ทราบ
